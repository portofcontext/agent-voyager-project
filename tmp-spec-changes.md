# Spec changes

Field and behavior changes made to the v0.1 specs during the cleanup, and why.
Doc structure and wording changes are not logged here.

Related changes share one row under the lowest ID; "Merges" lists the IDs it
absorbed. Absorbed and withdrawn IDs (C40, C53) are not reused.

| ID | Spec | Change | Reason |
|---|---|---|---|
| C1 | All | Rename the Descriptor's `spec_version` and the Commission's `schema_version` to `avp_version`, and add a required `avp_version` to every Trajectory event. | One name for the AVP version an object follows; `schema_version` read like the JSON Schema file's version. Events are read one at a time, so each needs its own copy now that CloudEvents' `specversion` is gone (C35). |
| C2 | All | Move the schema `$id` base from `https://avp.dev/schema/` to `https://www.agentvoyagerproject.com/schema/`. | `avp.dev` is not ours and never resolved. |
| C3 | All | Drop the `avp.` prefix everywhere. Descriptor: Tool `avp.mcp_server_id` becomes `mcp_server_id`, Skill `avp.source` becomes `source`. Trajectory: `data` keys become snake_case with no prefix (`avp.tool.call_id` becomes `tool_call_id`), and `type` values drop it (`avp.tool_invoked` becomes `tool_invoked`). Extensions go only in `meta`. Merges C33, C37; resolves Q4. | One name per concept across the three specs. The prefix only helps where AVP events share a stream with other producers' events, which no longer happens (C35). Dotted names were also ambiguous: `avp.cost.source` was a key, `avp.usage.input_tokens` a path. |
| C4 | Agent Descriptor | Skill `source` is a `file:` URI for the skill's directory, absent for skills with no files. | It had no format: Goose wrote `builtin://skills/<name>`, OpenCode `"<built-in>"`. A URI lets a supervisor match file-tool paths against it. |
| C5 | Agent Descriptor | Remove what nothing uses: `capabilities`, `prompt`, `default_model`, Subagent `avp.agent_type`, and the MCP server `status` value `pending`. Merges C6, C9, C13, C14. | No agent sets `capabilities`, `prompt`, or `agent_type`; conformance uses each case's `requires` list instead of `capabilities`. `default_model` can never apply, since the Commission requires `model`. `pending` records an unfinished connection. `prompt` is kept as a future idea. |
| C7 | Agent Descriptor | A Tool is an MCP `Tool` plus `mcp_server_id`, so `inputSchema` is required. A Skill is the Agent Skills frontmatter plus `source`, so `description` is required and `version` is removed. Merges C8. | Extend outside models; never change them. Agent Skills puts a version in `metadata`, and no agent sets `version`. |
| C10 | Agent Descriptor | Subagent: add optional `system_prompt`, `tools`, `mcp_servers`, `skills`; remove `inputSchema`. An absent list means none, so a subagent that shares the parent's items lists them again. | A supervisor reviewing a subagent's events needs its own prompt and tools. The tool that starts the subagent already has the input schema. One meaning for an absent list, with no `inherit` keyword. |
| C11 | Agent Descriptor | The Descriptor lists every built-in item, including ones a Commission turns off, and nothing a Commission adds or the agent finds in the workspace. The copy in `agent_described` matches the one produced before a run, except for MCP-provided tools and `status`. | The Descriptor says what the agent comes with; `agent_started` records what the run uses. The two copies no longer need caveats about how they differ. |
| C12 | Agent Descriptor | `supported_models` is information for supervisors. The agent no longer checks the Commission's model against it or fails with `unsupported_model`. | Choosing an agent that can run a model is the supervisor's job. No agent sets `supported_models`. |
| C15 | Commission, Trajectory | `prompt` is required on the Commission and on `agent_started`. Merges C43. | Every run starts with a prompt, and rebuilding the conversation starts from it. The only case without one was the Descriptor's `prompt` (C5). |
| C16 | Commission | stdio MCP server: remove `args`. | `command` is already the full argument list; every agent appended `args` to it. |
| C17 | Commission | A Commission's `system_prompt` replaces the Descriptor's, never adds to it. | Agents split: Claude replaced, Pi, Gemini, OpenCode, and Goose appended. The same Commission should give the same prompt on every agent. |
| C18 | Commission | MCP server: add optional `name` and `description`, as on the Descriptor's MCP server. | A server has the same fields whether it is built in or added. |
| C19 | Commission | The agent SHOULD refuse a Commission whose MCP server `id`s or skill names match its built-in ones (was MUST, with `commission_collision`). | No agent implemented the MUST, and no case tests it. A clash depends on the agent's built-in items, so it is one of the agent's refusal cases. |
| C20 | Commission | Replace the four `enabled_builtin_*` lists and `agent_versions` with one `agents` map: agent name to `{ version, enabled_tools, enabled_subagents, enabled_skills, enabled_mcp_servers }`. With `agents` present and no entry for the running agent, the agent refuses. An absent list allows all, `[]` allows none; `version` is an exact match. A turned-off item: the agent SHOULD NOT offer it to the model, and MUST NOT run it if called, recording the call as failed. Merges C25. | Five maps keyed by agent name, with opposite defaults for a missing key, become one lookup. Blocking the call is what keeps a run within its settings; some runtimes can deny a call but not hide the item. |
| C21 | Commission | The `origin` in `model` MUST be the model's maker; `provider` chooses the service that runs it, and `provider.id` is optional, defaulting to the origin. The agent sends its own model calls to `model` and doesn't switch; models that subagents or the runtime choose for their own calls are not covered. Refusing a `model` it can't run is a SHOULD. Merges C24, C29. | Using `origin` to pick an API (`openai/qwen2.5-7b` for a local server) put costs under the wrong price key. Runtimes legitimately use other models for subagents and helper calls, and most agents only learn that a model fails at the first call. |
| C22 | Agent Descriptor | `agent_name` matches `^[a-z0-9_-]+$`. | Keeps `agents` keys free to become patterns later (`acme-*`) without a breaking change. All nine agents already match. |
| C23 | Commission | A Secret reference is `{ "proxy": name }`, a credential a proxy outside the agent adds to its requests (only in `provider.credential` and HTTP `auth`), or `{ "env": name }`, a variable in the agent's environment (anywhere, including stdio `env` values). Supervisors SHOULD prefer `proxy`. An absent `credential` means the agent uses what its environment has; stdio `env` adds to what the agent's MCP client passes. Setting up the proxy and the environment is out of scope. Merges C63, C65; resolves Q1, Q6. | A Commission never holds a secret value, so the spec says where the value is without defining infrastructure. A proxy lets the agent use a credential without reading it, but only over HTTP, so a database password needs `env`. Passing a stdio server the whole environment would hand it every secret. The CLI's broker rewrote the Commission, which broke the no-secrets rule; a transparent proxy doesn't. |
| C26 | Commission, Trajectory | The error codes are `invalid_commission`, `mcp_connect_failed`, `auth_error`, `rate_limit`, `context_limit`, `agent_crash`, and `unknown`, each defined. `invalid_commission` replaces `commission_collision`, `unsupported_agent_version`, `unsupported_model`, and `unsupported_provider`. `agent_crash` covers model service failures and an interruption before `agent_started`. Supervisors treat an unknown code as `unknown`. Merges C52; resolves Q7. | The codes had no definitions. The four refusal codes needed the same response (fix the Commission or choose another agent), and nothing told them apart. Starting small is safe because the unknown-code rule lets codes, including retry hints, be added later. |
| C27 | Commission | The Skill `id` becomes a required `name` that equals its `SKILL.md` frontmatter `name` and follows the Agent Skills naming rules; the agent refuses a mismatch with `invalid_commission`. No two MCP servers share an `id`, and no two skills a `name`. Merges C64; resolves Q3. | Agent Skills requires a skill's directory name to equal its frontmatter `name`; a Commission skill has no directory, so `name` stands in for it. Duplicates made tool attribution and the clash check ambiguous. |
| C28 | Commission, Trajectory | If an MCP server in the Commission doesn't connect, the agent ends the run before its first model call with `mcp_connect_failed` (was: continue with the server `failed`). | A run without a server the Commission asked for isn't the run the supervisor defined. The code stays apart from `invalid_commission` because the response is to retry, not to fix the Commission. |
| C30 | Commission | With `output_schema`, the agent's final output MUST match it; how is up to the agent. The output is `agent_stopped`'s `output`. | Free text where structured output was asked for breaks a scorer silently. Agents without native support can use a tool whose input schema is `output_schema`. |
| C31 | Trajectory | A run that ends before `agent_started` (a refused Commission, a failed MCP server, a crash or interruption during startup) ends with `error_occurred` and has no `agent_stopped`. `agent_stopped` with reason `error` MUST follow an `error_occurred` that says why. A Trajectory is complete when it ends with `agent_stopped`, or with `error_occurred` before `agent_started`; supervisors MUST NOT treat an incomplete one as converged. Merges C54, C61. | `agent_stopped` reports how a started run ended; with no run there is nothing to stop. A stop for `error` otherwise has no cause. A killed agent can't send its last event, and a cut-off run shouldn't be scored by its last text. |
| C32 | Trajectory | An agent that can see a subagent's own model responses SHOULD record them (was MUST). | No Recorder could, so the MUST was unmet everywhere. |
| C34 | Trajectory | `meta` moves from `data` to the top level of the event. Remove `avp.correlation_id`, `trace_id`, `span_id`, `parent_span_id`, and the span-parent rules; OpenTelemetry leaves the README's Built on list. Merges C38, C57. | `data` holds only the fields of the event's `type`. Nothing in AVP reads the span fields or `correlation_id`, and the spans had the wrong shape for OpenTelemetry (one per event, not one per action). A converter builds spans from AVP's IDs. |
| C35 | Trajectory | Events are not CloudEvents: `specversion`, `source`, and `datacontenttype` are removed. A required `run_id` replaces `subject`: the Commission's `run_id`, or the agent's own ID without a Commission. The agent MUST NOT give two events the same `id`. Merges C36, C62. | Nothing in AVP uses CloudEvents: no package depends on it, and its three fields are constants nobody reads. A supervisor that forwards events to a broker converts them then. `subject` served as the run ID but was never required. With `source` gone, `id` alone must be unique. |
| C39 | Trajectory | Remove event fields nothing reads: `run_requested`'s `avp.supervisor.*`; `agent_started`'s `avp.operation.name`, `avp.thread_id`, `avp.tags`, `avp.session_id`; `assistant_message`'s `avp.response.time_to_first_chunk`, `avp.refusal.category`; `subagent_invoked`'s `avp.subagent.description`, `avp.subagent.run_id`; `subagent_returned`'s `avp.subagent.result.structured`. Merges C41, C45, C49. | Each one copies the Commission or Descriptor, is a constant, or has no producer. A runtime's own IDs, such as a session ID, go in `meta`. |
| C42 | Trajectory | `agent_started` and `assistant_message`: `avp.request.model` becomes a required `model`, an `origin/model` slug, and `avp.provider.name` becomes `provider_id`, absent meaning the model's origin. `assistant_message`'s `response_model` is also a slug, and `cost_source` is required. Merges C44. | Same names and meanings as the Commission (C21). Models were often bare SDK names, and `provider.name` meant the origin for most agents but the service for Goose. Without `cost_source`, a real `0` cost looks like an unknown one. |
| C46 | Trajectory | Usage holds its five token fields plus `cost_usd` and `cost_source` (moved from `assistant_message`), and nothing else; raw service usage goes in `meta`. Subagent usage is the same Usage with every field optional, plus `responses` (was `tokens_input`, `tokens_output`, `turns`). Merges C47. | Supervisors total tokens and spend together, so one object holds both, with one set of names at both levels. Extra counts came in shapes no supervisor could rely on. |
| C48 | Trajectory | `tool_invoked`: remove `avp.tool.dispatch_target`; add optional `mcp_server_id`. | `dispatch_target` said `mcp_server` but not which one. `mcp_server_id` matches the Descriptor's Tool and tells same-named tools apart. |
| C50 | Trajectory | `subagent_invoked` and `subagent_returned` carry the subagent's own `invocation_id`. An optional `subagent_invocation_id` on `assistant_message`, `tool_invoked`, `tool_returned`, `subagent_invoked`, `subagent_returned`, and `error_occurred` names the subagent the event belongs to, absent for the main agent. Agents SHOULD report a subagent's own events, and each one reported MUST carry it. Merges C58, C59. | With spans gone (C34), it is the only link from an event to its subagent, and one field filters a subagent's events. One meaning on every event also links a nested subagent to its parent. |
| C51 | Trajectory | Content blocks: remove `audio`, `video`, and `document`, and the `url` and `file` image sources; image data is always base64. | No agent produces them. Non-text data is a future idea. |
| C55 | Trajectory | When a tool call started a subagent, the call's `tool_returned` has `is_error` `true` exactly when `subagent_reason` isn't `converged` (was: set only for `converged` and `error`). | `refused`, `interrupted`, and `abandoned` subagents also give the model no answer. |
| C56 | Trajectory | Remove `step` from every event that had it. | Its links are already in the Trajectory: event order, and the `tool_use` block with the same `tool_call_id`. It was used only for display. |
| C60 | Trajectory | Supervisors MUST skip an event whose `type` they don't know (was: no rule). | Later versions can add event types without breaking supervisors, as with error codes (C26). |
